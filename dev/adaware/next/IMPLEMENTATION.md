# Implementation notes — transcript ad detection (M0/M1/M2)

Branch `feature/adaware_dev_M0`. Research method: `dev/adaware/next/RESULTS.md`.

## M0 — data, training, export

Code: `dev/adaware/next/m0/`

- `collect.py` — one episode per show, two sibling takes, faster-whisper small on GPU,
  labels from the 4-word-shingle sibling diff, audio deleted in a `finally` block.
  Peak disk is one episode; the corpus is text only. Resumable via
  `corpus/manifest.json`.
- `merge_legacy.py` — folds the original ten-episode v3 corpus into the M0 corpus as
  training data (test shows excluded).
- `train.py` — word 1-2 gram + `char_wb` 3-5 gram TF-IDF, balanced logistic classifier,
  semi-Markov pod decoder tuned on episode-grouped inner folds, held-out-show evaluation,
  exports `bundle/model.json` and Kotlin parity fixtures. **Retired** on branch
  `feature/adaware_jev` (jev classifier instead); moved to `next/m0/retired_tfidf/`.

Commands:

```bash
cd dev/adaware
uv run python -u next/m0/collect.py --per-show 1 --limit 150
uv run python next/m0/merge_legacy.py
```

### Evaluated so far

Corpus at the time of writing: 32 labelled episodes (20 train / 12 held-out episodes from
5 held-out shows), 55,528 transcript segments, 7.3% ad segments.

| split | strict P | strict R | frame P | frame R | frame AP |
|---|---|---|---|---|---|
| train (in-sample) | 0.485 | 0.503 | — | — | 0.888 |
| held-out shows | 0.092 | 0.092 | 0.416 | 0.540 | 0.316 |

Strict = one-to-one pod match with both boundaries within 10 s. The held-out number is far
from the 0.90 target and the corpus is short of the ~100-episode goal; collection is still
running and the number moves as it grows (21 episodes: 0.075 / 0.097; 32: 0.092 / 0.092 on
a different test set). This is consistent with RESULTS.md: the transcript signal identifies
ad copy well (frame AP) but edges and isolated hosted promos are hard, and sibling-diff
labels are narrower than real pods.

`publish.py` retrained and copied the bundle into the Android module and test resources in
one step. `finish.sh` waited for the collector, then merged and published. Both are retired
on `feature/adaware_jev` and sit in `next/m0/retired_tfidf/`; the exported bundle is gone.

### Speech to text

ML Kit's GenAI **Advanced** speech recognizer (`com.google.mlkit:genai-speech-recognition`)
was removed on `feature/adaware_jev_moonshine`. It handed the downloaded file over as a
one-shot `AudioSource.fromFile`, and one-shot sources cannot report word timings: the
recognizer returned ordered segments with no clock, and cue times had to be reconstructed
from 20 ms audio-energy frames (`AudioAdDecoder` → `detectSpeechRegions` →
`alignSegmentsToRegions`). Those cues were **speech-region accurate, not word accurate**:
a segment started where speech resumed around it, a pause inside a long segment pulled its
edges towards its neighbours, and flat audio collapsed into one region covering the whole
clip. That is what made ad boundaries land in the wrong place.

Its first replacement, on `feature/adaware_jev_moonshine`, was Moonshine
(`ai.moonshine:moonshine-voice`): streaming models with word-level times from cross-attention DTW,
one bundle per language. That engine is retired on `feature/adaware_parakeet` — ONNX Runtime, the
per-language bundles and the DTW cue rules went with it, and `dev/adaware/next/moonshine/` was
deleted rather than carried forward, because its research and scoring described an engine that no
longer exists.

Speech to text is now NVIDIA **Parakeet TDT 0.6B v3**, run through MediaPipe's audio transcriber
(`com.google.mediapipe:tasks-audio`, CPU only) from the LiteRT-LM export
`parakeet_tdt_0.6b_v3_5s_i8_stateful.litertlm` (614 588 752 bytes, CC-BY-4.0, downloaded on demand
into `noBackupFilesDir/parakeet-model` rather than bundled). MediaPipe reports the text as fixed ~1.25 s
windows with a start and an end, not as sentences, so cues are assembled from the text and take their
times from the windows those characters came from; there is no word alignment to trust and no offset
to correct. One measured pass over a 34 s clip logged `rtf=2.05` on a cold bundle, and the measurement
that matters is always the `rtf` on the `ParakeetStt` log line. Model install and the log field
reference live in `dev/adaware/next/parakeet/`.

The phone app's `repositories` module no longer sets `minSdk = 26`: MediaPipe's AAR declares 24, so
the module is back on the project's floor and the engine check is the runtime one. The app still
never records audio — it only hands the engine audio it already has.


### Pipeline and storage

- `TranscriptAdAnalyzer` runs off the playback thread: STT → cue list → TF-IDF/decode →
  `DbAdSegment`s (`origin = Transcript`, `kind = Ad`) → `AdSegmentDao.replaceAll`, then
  marks `AdAnalysisState` complete. User deselection is preserved across re-analysis by
  pod start second.
- Confidence is fixed at 0.4, **below** the auto-skip threshold. The model is not
  calibrated; results are suggestions until an independent evaluation clears the gate.
- Transcripts are written as WebVTT to `files/on-device-transcripts/<uuid>.vtt` and
  registered in `episode_transcript` with `local-generated://<uuid>` and
  `isGenerated = true`, so the existing transcript UI and tap-to-seek work unchanged.
  `TranscriptManagerImpl` reads that scheme from disk instead of the network. Saving
  upserts only the on-device row, so a server transcript for the same episode survives.
- `AdAnalysisScheduler` enqueues unique `TranscriptAdAnalysisWorker` work after a
  successful `DownloadEpisodeWorker` (battery-not-low constraint), gated by
  `Feature.AD_SKIPPING`. Opening a downloaded episode's details also calls `schedule`, so
  a missed or interrupted pass is retried without playback, and the details screen shows a
  "Generating transcript…" banner while the work is queued or running.
- **Analysis identity.** `episode_ad_analysis` stores an audio signature (size +
  last-modified), the model identity (bundle version + vocabulary hash) and the STT
  version (migration 142→143). A completed analysis is reused only when all three match;
  stale transcript-origin results are deleted and re-analysed, while audio-only rows
  (empty identities) are left for the fallback path. A re-download, a new model bundle or
  a recognizer change therefore cannot serve old segments.
- `AdSegmentManagerImpl.analyze` tries the transcript analyzer for downloaded episodes and
  falls back to the existing audio analyzer for streams, missing files, unsupported
  devices, or failed STT. Streaming therefore keeps on-the-fly detection through the
  audio path (it follows the ExoPlayer cache ahead of the playhead).

## M2 — transcript tab

`modules/features/player/.../player/view/transcript/TranscriptTabFragment.kt` adds a
**Transcript** tab to the player pager, shown when a transcript exists for the current
episode (`ShelfSharedViewModel.uiState.isTranscriptAvailable`). Each cue shows its text and
`m:ss` timestamp; tapping seeks playback to the cue start. It reads the same transcript
stack, so an on-device transcript appears as soon as analysis finishes.

The same fragment also serves a **Transcript** tab on the episode details sheet
(`EpisodeContainerFragment`), created with `forEpisode(uuid)` so it shows that episode
without playback and in the app colors. The details tab appears as soon as
`transcriptDao.observeTranscripts` reports a transcript, which means the background
analysis does not need the player to be open. The Details tab's transcript card follows the
same availability flow, so it appears live when the analysis completes.

The **Ask AI** tab (formerly "AI") follows the same rule in both places: it is a chat over
the transcript, so it appears next to the Transcript tab whenever one exists.
`AiTabFragment.forEpisode(uuid)` gives it the same fixed-episode, app-color mode as the
transcript tab for the details sheet.

Two places used to take the on-device transcript away after it was produced:
`TranscriptDao.replaceAll` (a show notes refresh) and `DownloadManager.cleanUpDownloads`
(deleting a download) both deleted every transcript row of the episode. Both now keep
`local-generated://` rows, and the download cleanup clears only the ad segments and the
analysis state, so the transcript stays readable after the download is gone.

## Review follow-up (this pass)

- Chunked STT distinguishes expected no-speech from fatal errors; a fatal chunk fails the
  pass, resources close in `finally`, cancellation propagates, and the analyzer no longer
  persists partial transcripts or completes the state.
- Stale-result prevention: audio signature + model + STT identities stored in
  `episode_ad_analysis` (migration 142→143), reuse only on exact match, stale
  transcript-origin results invalidated. Local transcript writes no longer delete server
  transcripts.
- Collection resume now retries `error` entries up to `--max-attempts` while preserving
  `ok` and `no-labels`; ad-stitching hosts are ordered first and takes download in
  parallel.
- `finish.sh` waits for the collector, then merges and publishes a fresh bundle.

## Open items
